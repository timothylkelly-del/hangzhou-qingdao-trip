## 自动天气怎样更新

自动预报使用 [Open-Meteo](https://open-meteo.com/) 免费非商业接口，按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 标注来源。一次请求杭州、连云港、日照、青岛、莱州、威海、烟台、大连8座城市的16天预报，按北京时间和准确的 `YYYY-MM-DD` 日期匹配11天、20个城市/日期位置，包含10月6日提前返杭的杭州备选。转场日同时显示两端天气。

- 打开页面时检查更新；页面可见时每15分钟检查一次。
- 返回页面或网络恢复时检查缓存，距上次成功同步不足15分钟时复用缓存。
- 可点“立即更新天气”手动刷新；请求有超时、并发保护和短时间重复点击限制。
- 同步成功后更新气温、天气、降水概率、风速、阵风和每日穿衣建议；未完整发布的日期显示待发布，空值不会显示成0℃或晴天。
- 上次成功数据保存在当前浏览器的 `localStorage`。更新失败时保留缓存并显示同步时间；没有可用缓存时才显示2026年9月20日中国天气网备用快照，明确标为旧数据。
- 过去日期不作为未来预报展示；北京时间2026年10月7日结束后停止自动请求，页面持续打开跨日也会检查结束日期。

**最近同步时间是本页面取回数据的时间，不是预报发布时间。** 天气源按其模型周期更新，网页同步不代表秒级天气实况。7天及以后只作远期趋势，模型未提供完整值时继续等待；16天请求范围不保证所有日期、字段均已有数据。

自动数据与9月20日的中国天气网备用快照来自不同来源，不混称同一预报。各城市中国天气网入口保留，便于临行交叉核对。天气数据和每日穿衣建议在浏览器中刷新，不要求每次预报变化都重新提交仓库；关闭页面时不在后台持续运行。

城市天气不能替代海况、沿途路况、景区开放或承运通知。烟台—大连跨海仍须单独查风浪、能见度、客船和运车船运行；城市风速不代表海面风浪或开航许可。穿衣数量和温度搭配分档是本团建议，不是官方统一标准。

## 可维护项目结构

- `index.html`：生成后的公开站点入口；`trip.html`兼容原入口。
- `data/guide.json`：接站、返杭硬节点与D1—D11日程；`data/hotels.json`及`data/sources.json`保存住宿候选和行程来源。
- `data/weather.json`：固定行程日期、各日城市、照护与备用建议，以及有来源时间的中国天气网备用数据。
- `data/weather-locations.json`：自动天气使用的8城坐标；`data/clothing-sources.json`为穿衣建议资料来源。
- `templates/`：日程、交通、船运、住宿、安全、衣物和样式片段；`templates/v8-base.html`保留原设计底稿。
- `scripts/render_guide.py`：从数据和模板生成入口；`scripts/weather_book.py`生成天气卡片及配置。
- `scripts/weather-core.js`：日期、空值、单位与坐标验证、预报整理、穿衣逻辑和API请求地址。
- `scripts/weather-live.js`：页面同步、缓存、失败回退和过期停止；`scripts/guide.js`负责其余页面交互。
- `scripts/photo_book.py`、`data/photos-*.json`、`assets/photos/`及`assets/review-*.jpg`：实景照片、地点映射、来源作者及许可状态。
- `assets/route-map.svg`：区域路线示意，不是行车导航或船舶航迹。
- `scripts/build_offline.py`：内嵌静态资源并校验，生成本地单文件；实时天气仍需联网。
- `tests/weather-core.test.js`：使用Node内置测试验证天气逻辑。

公共仓库保留维护所需源码、数据和静态资源，**不上传**`dist/`、`docs/`、`REVIEW.md`、`__pycache__/`或`data/weather-south.json`、`data/weather-north.json`原始天气快照。本地保留旧版单文件、原始调研、抓取快照和验证记录；从公共仓库重新构建不依赖这些本地记录。

## 修改、构建与验证

在项目根目录执行：

```sh
python3 scripts/render_guide.py
python3 scripts/build_offline.py
node --check scripts/guide.js
node --check scripts/weather-core.js
node --check scripts/weather-live.js
node --test tests/weather-core.test.js
```

Python构建仅用标准库；天气单元测试使用Node内置`node:test`，不需要安装第三方依赖。修改优先落在`data/`、`templates/`和`scripts/`，直接修改生成后的`index.html`会在下次构建时被覆盖。

本机预览：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

查看 `http://127.0.0.1:8765/`，核对天气状态、日期、图片及手机布局。已完成的本地真实接口请求显示14/20个地点日期有预报、6处待覆盖；这是当次验证结果，会随天气源覆盖范围变化。

GitHub Pages沿用既有`main`根目录。完成内容更新、构建和受影响检查后再提交部署，并通过无需登录的公开链接验证实际线上版本与天气请求；仓库推送成功本身不等同于网站部署成功。天气服务请求失败、浏览器禁用脚本或网络不可达时，页面会保留已标明日期的备用内容，不能将其当作最新天气。
